# v1 accessibility review

Automated checks use axe with WCAG 2 A/AA and WCAG 2.1 AA rules. Coverage includes sign in, sign up, signed-in Home, Decks, a populated Deck builder, a waiting Room, the Match battlefield, an active Play Preview and the Match menu. These checks include rendered text contrast. The full keyboard Match test in `preview.spec.ts` plays through Redraw, card selection, Rows, Pass and Round results without pointer input.

Faction tint is redundant with the printed Swarm/Court/Neutral labels; it never identifies a choice by colour alone. Row symbols have distinct shapes and accessible Close/Ranged/Siege names. Strength changes show signed numbers alongside raised/lowered colours; destroyed cards and drawn cards are also described in the Play Preview. Gems expose a numeric accessible label. These redundant text and shape cues preserve the information when orange/blue or red/green differences are hard to distinguish.

Modal dialogs contain Tab and Shift+Tab, isolate background controls and restore focus. Keyboard Card Detail focuses its Close control; battlefield Units and cards in pile overlays can receive focus for the I shortcut. Local Room Seat switching remains a development control for driving the other player, outside the modal's product UI.

Reduced motion disables CSS animation and transitions. Match event animations use opacity only when the preference is set; changing the preference during movement finishes the queue immediately. Existing and additional Playwright tests verify both cases.

Axe and keyboard automation do not replace testing with real assistive technology. This review records the implemented semantics and tested screens; it does not claim a manual screen-reader certification.

Clerk authentication adds a Display name onboarding screen and account settings form. Onboarding focuses the nickname field; labels describe its limits and non-unique nature, and save/error feedback uses status/alert semantics. Automated axe checks cover these game-owned screens with the controlled Clerk fixture. Clerk's hosted sign-in and security controls need the separate real-provider keyboard/screen-reader smoke test described in `docs/authentication.md`.
